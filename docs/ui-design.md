## 1. コンセプト「夜更けのギルドホール」

ギルドは、腕に覚えのある者が集まり、依頼を受け、互いの知恵を借りる場所。AIギルドでは、手を動かす者・調べる者・束ねる者・異を唱える者など役割の違うエージェントと、ギルドの主である**あなた**が同じ卓を囲む。マネージャーが依頼を分けて割り振れば、ギルドは一つの依頼を手分けして片づける。

画面は夜更けのギルドホール。墨色の静かな面に、**いま働いている仲間のところだけ灯（あかり）がともる**。羊皮紙・剣・盾のようなファンタジーの飾りには頼らない。ギルドから借りるのは「灯」「菱の紋」「卓を囲む」という構造だけで、毎日使う道具として現代的に組み立てる。

ギルドの紋は**菱（◇）に灯（●）**。役割の印も同じ菱を小さく色違いにしたもの（先頭タグの色。§2）。人間だけは丸（●）。

### 5 つの原則

1. **静かな面、意味のある色** — 面は藍墨のニュートラル。色を使うのは「誰か（役割の色）」「いま何が起きているか（灯・状態）」「次に何をするか（主ボタン）」の 3 つだけ。飾りの色は置かない。
2. **丸は人、角は AI** — アバターの形で人と AI を見分ける。人間は円、エージェントは角丸の正方形。役割は先頭タグの色の札で見分ける。色だけに頼らない（札には必ず文字がある）。
3. **灯がともる** — 動作中は金の灯。紋（ロゴ）・アバター・チャンネル・ヘッダーで同じ灯を使い、2 秒周期でゆっくり呼吸する。点滅・回転・スピナーは使わない。
4. **会話は読み物** — AI は長文を書く。本文は 15px・行間 1.7・最大 46 字幅・禁則 strict で、読み物として組む。UI の枠（14px）より本文を一段大きくする。
5. **受付係の声** — 文言はギルドの受付係のように、丁寧で短く、少しだけ温かく。ロールプレイはしない。主語はいつも名前（§8）。

## 2. 見分け方

| 対象 | 形 | 色 | 札 | 備考 |
|---|---|---|---|---|
| 人間（あなた） | **円** | タイルは個人色（`Profile.color`）。人の色は金 `--kind-human` | なし。メンバー一覧で「あなた」 | 金を使うのは「あなた」の表示と自分宛てメンションだけ |
| エージェント | **角丸** `--radius-avatar` | 先頭タグの色（下の表。決まらなければ中立） | 先頭タグの塗りの札 | サイドバーとメンバーは先頭タグで区分し、区分の見出しに同じ色の菱 ◆ |
| システム | アバターなし。左の列に小さな線画アイコン | 文字は `--text-secondary` | なし | §5.4 |
| 削除済みのエージェント | 角丸・**灰色で半透明** | なし | 札を出さず、名前の後ろに「（削除済み）」 | 過去の発言にだけ現れる（§6.4） |

### 役割の色 — 色相の秩序

エージェントに「種別」はない。振る舞いは本人の設定で決まり、見た目の区分は**タグ**（先頭のタグが区分）。テンプレート（作業者・専門家・マネージャー…）は作成時のプリセットで、それぞれ色（`accent`）を 1 つ持つ。

| 色 | トークン | テンプレート | 色相 | 置いた理由 |
|---|---|---|---|---|
| 若葉 | `--kind-enduser` | エンドユーザー役 | 122° | 人の代わりに使ってみる役。あなた（金）のいちばん隣。若葉マークの色 |
| 若竹 | `--kind-worker` | 作業者 | 168° | 手を動かす |
| 青磁 | `--kind-scribe` | 書記 | 205° | 記録する。彩度を落とした控えめな色 |
| 露草 | `--kind-researcher` | 調査係 | 237° | 調べる |
| 群青 | `--kind-manager` | マネージャー | 272° | 束ねる |
| 藤 | `--kind-expert` | 専門家 | 300° | 知恵を貸す |
| 牡丹 | `--kind-critic` | 批判役 | 343° | 異を唱える。注意の赤の手前 |
| 中立 | `--kind-neutral` | テンプレートに無いタグ・タグなし | – | 色で意味を付けない |

- **暖色の半分は人と状態に取っておく**: 紅 18°（エラー）・柿 58°（注意）・金 78°（あなた・灯・主ボタン）・山吹 92°（自発）。役割の色は寒色側の半分にだけ置き、**あなたに近い役ほど金の近く**に並べる（人の代わりのエンドユーザー役 → 手 → 記録 → 調査 → 束ね → 知恵 → 反論）。役割の札が状態（注意・エラー・完了）に見えないための秩序でもある。
- **色を付けるのは**: タグの札（塗り）・メンションのチップ・サイドバーとメンバーの区分の菱・プレビューの札。名前や本文の文字、面の地には使わない。
- **色の決め方**: タグ `t` に色が付くのは、`Snapshot.templates` に `defaults.tags[0] === t` のテンプレートがあるときだけ。その `accent` から `var(--kind-<accent>, var(--kind-neutral))`（地は `var(--kind-<accent>-soft, var(--kind-neutral-soft))`）を組み立てる。値で分岐しない。エージェントの区分の色＝先頭タグの色。
- **テンプレートを足すとき**: tokens.css と tokens-light.css に `--kind-<accent>` と `-soft` を足す。色相は空いている所（いまは 130°〜160°・215°〜230°・310°〜330° など）から、意味の近い役の隣を選ぶ。両テーマで AA（`-soft` の地の上・ホバー中で 4.5:1 以上）を確かめる。
- **リンクは色ではなく下線で示す**（青は役割の色に使うため。`--text-link` はほぼ本文の色で、下線を常に引く）。
- **バックエンドは色を付けない**。等幅・線の札（BackendTag）に `BackendInfo.id`（`claude` / `codex`）を出し、`label` はツールチップと編集画面に出す。バックエンドは将来増える文字列なので、色を割り当てると破綻する。会話の理解には役割と人格のほうが大事なので、**役割 = 塗りの札、バックエンド = 線の札** で強弱をつける。
- **個人色（`Agent.color`）はアバターのタイルにだけ使う**。名前の文字色にはしない（任意の色では AA を保証できない）。タイル = 個人色を面に溶かす:
  `background: color-mix(in oklab, var(--avatar-color) var(--avatar-tint), var(--avatar-tint-base)); box-shadow: inset 0 0 0 1px color-mix(in oklab, var(--avatar-color) 38%, transparent);`
- **個人色の見本 12 色**（エージェント編集の色見本と新規作成時の割り当て順。`src/shared/lib/colors.ts` の候補をこれに置き換える）:

| 朱 | 柿 | 山吹 | 萌黄 | 若竹 | 青磁 | 浅葱 | 群青 | 藤 | 菖蒲 | 桜 | 鈍 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| `#ea856b` | `#e28d4f` | `#cb9d2a` | `#91b34d` | `#4cbd88` | `#00beb7` | `#22b5e1` | `#7ca2f6` | `#b191ea` | `#d285cb` | `#e680a1` | `#9199a5` |

  初期データの推奨: ハル 山吹 / ソラ 浅葱 / ロジカ 群青 / ギア 柿 / カナメ 菖蒲。個人色はアバターのタイル（淡く溶かした地）にしか出ないので、役割の色（札の文字色）とは混ざらない。

## 3. トークン

### 3.1 面（奥ほど暗く、手前ほど明るい）

| トークン | 使う場所 |
|---|---|
| `--bg-sunken` | コードブロック、セグメントの溝、復旧画面の場所表示など「一段沈んだ」所 |
| `--bg-sidebar` | 左サイドバー、復旧画面の背景 |
| `--bg-panel` | 右のメンバーパネル |
| `--bg-app` | 中央（チャンネル）、ボード状のカード |
| `--bg-input` | 入力欄・テキストエリア・セレクト |
| `--bg-elevated` | ダイアログ・ポップオーバー・メニュー・トースト |
| `--bg-hover` / `--bg-active` | 半透明の重ね。ホバー / 選択・押下。どの面の上でも同じ手ざわりになる。広い面の地には使わない |
| `--bg-overlay` | ダイアログの背景の幕 |

- **浮いている面の公式**: `--bg-elevated` + `1px solid var(--border-subtle)` + 影（ポップオーバー・トーストは `--shadow-md`、ダイアログは `--shadow-lg`）+ 角丸（`--radius-md` / ダイアログは `--radius-xl`）。
- **`--surface`**: いま乗っている面の色。面を持つ容器（サイドバー・パネル・ダイアログ・ポップオーバー）は `--surface: var(--bg-sidebar)` のように上書きする。灯や選択中の色見本の「切り抜きの縁」はこれを使う（`box-shadow: 0 0 0 2px var(--surface)`）。`--bg-sidebar` を直書きすると別の面で縁が浮く。
- 枠線: 区切りは `--border-subtle`、入力欄やボタンの枠は `--border-strong`、そのホバーは `--border-hover`。入力欄のフォーカスは枠 `--focus-color` + にじみ `0 0 0 2px var(--focus-glow)`。`--border-focus` は**常にフォーカスがある入力欄（コンポーザー）だけ**の静かな枠。

### 3.2 文字色

| トークン | 使う場所 | コントラスト（両テーマ・6 つの面 × 通常 / ホバー / 選択中の最悪値） |
|---|---|---|
| `--text-primary` | 本文・名前・見出し | 9.7 以上 |
| `--text-secondary` | 補助文・システム発言・説明 | 6.3 以上 |
| `--text-muted` | 時刻・プレースホルダ・件数・メタ情報 | 4.5 以上 |
| `--text-on-accent` / `--text-on-danger` | 金 / 紅の塗りの上の文字（ホバー中も） | 6.6 以上 |
| `--text-link` | リンク | 4.9 以上 |
| `--accent-text` | 面の上に金で文字を書くとき（ライトでは暗い金） | 5.0 以上 |

`--text-muted` も 4.5:1 を満たすので小さな文字に使ってよい。ただし **金を文字に使うときは必ず `--accent-text`**（`--accent` はライトで白地 1.9:1 になる塗り専用の色）。

### 3.3 意味の色

| トークン | 意味 | 主な使い方 |
|---|---|---|
| `--accent` / `-hover` / `-soft` | 灯の金。操作の主役 | 主ボタンの塗り、スイッチのオン、選択中のラジオカードの枠と面 |
| `--focus-color` / `--focus-glow` | フォーカス | キーボード操作の輪（global が自動で付ける）、入力欄の枠とにじみ |
| `--activity` / `--activity-glow` | 灯（動作中） | 灯の点と、そのにじみ |
| `--kind-<accent>`（7 色）/ `--kind-neutral` / `--kind-human`（各 `-soft`） | 役割・人 | タグとメンションのチップ・区分の菱。文字色にも点にも使える明度（§2） |
| `--autonomous` / `-soft` | 💡 自発 | 自発投稿の札 |
| `--mention-bg` / `--mention-text` | 色の決まらない相手 | 先頭タグがテンプレートに無い人・削除済みのメンション（中立） |
| `--mention-self-bg` | 自分宛て | 自分がメンションされた発言の行の地（左に 2px の `--kind-human` の線） |
| `--danger` / `-hover` / `-soft` | エラー・削除 | エラー発言の面、検証エラー、危険なボタン |
| `--warning` / `-soft` | 注意 | ログインが必要、危険な権限、上限の告知 |
| `--success` / `-soft` | 完了・準備 OK | トーストのチェック、バックエンドの準備 OK、タスクの完了 |
| `--selection-bg` | 文字の選択 | global が設定済み |

塗りの札・チップは「`-soft` の地 + 同じ色の文字」が基本（どれも AA を確認済み）。

### 3.4 文字組み

| トークン | 値 | 使う場所 |
|---|---|---|
| `--text-2xl` | 26px | オンボーディング・大きな空の状態 |
| `--text-xl` | 20px | 空の状態・復旧画面の見出し、編集プレビューの名前 |
| `--text-lg` | 16px | チャンネル名（ヘッダー）、ダイアログの見出し |
| `--text-body` | 15px | **メッセージ本文・入力欄**（打つ文字と投稿の大きさを揃える） |
| `--text-md` | 14px | UI の標準: 行・ボタン・入力欄・名前・システム発言 |
| `--text-code` | 13px | コードブロック |
| `--text-sm` | 12px | 補助文・札・小見出し・ヘルプ・エラー文。**日本語の最小** |
| `--text-xs` | 11px | **英数字だけ**（時刻・バックエンド名・件数）。日本語には使わない |

- 行間: `--leading-tight` 1.35（見出し・1 行のラベル）、`--leading-snug` 1.5（UI の複数行・説明文。body の既定）、`--leading-normal` 1.7（本文）。
- 字間: body に `--tracking-normal` 0.02em。小見出しのラベルは `--tracking-wide` 0.08em。数字と等幅は 0。
- 太さ: `--weight-regular` 400 本文 / `--weight-medium` 500 選択中の行・ボタン・チップ / `--weight-semibold` 600 ラベル・主ボタン / `--weight-bold` 700 名前・見出し。
  游ゴシック UI（Noto Sans JP の無い古い Windows）は 500 を持たず 400 で表示される。**必ず太く見せたい所は 600**。
- 書体: Windows は英数字 Segoe UI Variable + かな漢字 Noto Sans JP（無ければ游ゴシック UI）。macOS は SF + ヒラギノ。外部フォントは読まない。
- global.css で全体に効いているもの: 禁則 `line-break: strict`、和欧間の空き `text-autospace`、段落の泣き別れ防止 `text-wrap: pretty`、見出しの `palt`（かな詰め）と `word-break: auto-phrase`（文節で折り返す）、`em` は斜体にせず太さで強調（和文の偽斜体を避ける）。
- 数字が並ぶ所（時刻・件数）は `font-variant-numeric: tabular-nums`。
- 短い説明文（空の状態・復旧画面・ダイアログの説明）には `word-break: auto-phrase` を足してよい（「ファンタ／ジー」のような語の途中の改行を防ぐ）。長い本文（メッセージ）には使わない（行末が不揃いになりすぎる）。
- インラインのチップ（メンション・インラインコード）は `box-decoration-break: clone`（と `-webkit-` 版）で、折り返しても両端の余白と角丸を保つ。

### 3.5 余白とリズム

4px 単位（`--space-0-5` 2px 〜 `--space-16` 64px）。目安:

| 関係 | 値 |
|---|---|
| 札の中、アイコンと文字 | `--space-1`〜6px |
| 行の中の要素の間、ボタン同士 | `--space-2` |
| アバターと本文、ラベルと入力 | `--space-3` / 6px |
| ダイアログの入力欄同士 | `--space-5` |
| ダイアログの内側、ボードの内側 | `--space-6` |
| 画面の区画の間 | `--space-10`〜`--space-16` |

### 3.6 角丸・影・動き

- 角丸: 札・チップ `--radius-sm`、ボタン・入力・行 `--radius-md`、入力欄の枠・カード `--radius-lg`、ダイアログ `--radius-xl`、エージェントのアバター `--radius-avatar`（30%）、人間のアバター・灯・スイッチ `--radius-full`。
- 影: 静止している面には付けない。浮くもの（ポップオーバー `--shadow-md`、ダイアログ `--shadow-lg`）とセグメントの選択中（`--shadow-sm`）だけ。
- 時間: 色の変化 `--duration-fast` 120ms、開閉・スイッチ `--duration-normal` 200ms、ダイアログの登場 `--duration-slow` 320ms。曲線は `--ease-standard`、現れるときは `--ease-out`。
- キーフレームは名前ではなく**トークンで参照**する（CSS Modules が名前を書き換えるため）: `animation: var(--animation-lamp)`（灯）/ `var(--animation-rise)`（ポップオーバー・ダイアログ・トースト）/ `var(--animation-fade)`（幕・新着の行）。
- 「視差効果を減らす」設定では global が時間を 0 にし、アニメーションを最後の姿で止める。**キーフレームの最後の姿 = 要素の素の姿** にしてあるので、動きを止めても正しく見える。コンポーネントで `@media (prefers-reduced-motion)` を書き足す必要はない。

### 5.8 ボタン

高さは `--control-md`（小 `--control-sm`）で固定し、左右 `--space-4`（小 `--space-3`）、`--radius-md`、`--text-md` medium、アイコンと文字の間 6px、`white-space: nowrap; flex: none;`（狭い所で「停／止」と縦に割れないように）。

| 種類 | 通常 | ホバー | 使う場所 |
|---|---|---|---|
| 主（primary） | `--accent` 地・`--text-on-accent`・semibold | `--accent-hover` | 1 画面に 1 つ（作成・保存・送信・再試行） |

| ゴースト | 地なし・secondary | `--bg-hover`・primary | 補助操作・リンク的な操作 |
| 危険 | `--danger-soft` 地・`--danger` 文字 | `--danger` 地・**`--text-on-danger`** | 削除の入口 |
| 危険（確定） | `--danger` 地・`--text-on-danger`・semibold | `--danger-hover` | 確認ダイアログの「削除する」だけ |
| アイコン | 28px 正方形・muted | `--bg-hover`・primary。オンは `aria-pressed` で `--bg-active` | ヘッダー・行の操作 |

### 5.9 入力部品

- **テキスト入力**: 高さ `--control-md`、左右 `--space-3`、`--bg-input`、`1px solid var(--border-strong)`、`--radius-md`、`--text-md`。ホバー `--border-hover`。フォーカスは枠 `--focus-color` + `0 0 0 2px var(--focus-glow)`（3px の淡い金は暗い面で泥色に見えるので、細く澄ませる）。エラー `aria-invalid="true"` で枠 `--danger`、フォーカス時のにじみは `0 0 0 2px var(--danger-soft)`。無効は opacity 0.5。セレクトは長い選択肢を `text-overflow: ellipsis` で切る。

- **ヘルプ** `--text-sm` muted / **エラー文** `--text-sm` `--danger`、先頭に 14px の ⚠。`aria-describedby` で入力に結ぶ。どちらも 11px にしない。

### 5.10 汎用フォーム（バックエンド固有設定 `BackendInfo.options`）と検証エラー

**モデルと推論の深さ**（頭脳の区画。`BackendInfo.models`）:
- モデル: セレクト。先頭は「既定（{既定のモデルの label}）」（`defaultModel` が空なら「既定（バックエンドに任せる）」）、続いて `models` の label。ヘルプは選んでいるモデル（既定なら既定のモデル）の `description`。保存されているモデルが一覧に無ければ「{id}（一覧にありません）」を足して保つ。`models` が空ならテキスト入力（プレースホルダ「既定: {defaultModel}」）。
- 推論の深さ: セレクト。選んでいるモデルの `efforts` があるときだけ出す。先頭は「既定（{defaultEffort}）」（null なら「既定（モデルに任せる）」）、続いて efforts（値をそのまま）。選択肢が 5 つ以上になりうるので、セグメントにはしない。
- バックエンドを変えるとモデルと深さを既定に戻し、モデルを変えて深さがそのモデルで選べなくなったら深さを既定に戻す。保存されている深さがモデルで選べなければ「{effort}（このモデルでは選べません）」を足し、入力の下にエラー文を出す。

`OptionSpec` を次の部品に写す。ラベル = `label`、ヘルプ = `description`。

| type | 部品 | 補足 |
|---|---|---|
| `string` | テキスト入力 | プレースホルダに「既定: {default}」（default が空なら出さない） |
| `number` | テキスト入力（`type="number"`、幅 10em、`tabular-nums`） | 同上 |
| `boolean` | スイッチの行（左にラベルとヘルプ、右にスイッチ） | – |
| `select` | 選択肢が 4 つ以下で短ければセグメント、それ以外はセレクト | `default` の選択肢に「（既定）」を添える |

- 置き場所: エージェント編集の「{label} の詳細設定」区画（見出しは小見出しのラベル）。すべて既定値なら畳んでおき（`<details>`、要約「詳細設定」）、既定と違う値があれば開いておく。
- 値が既定と違う項目は、ラベルの右端に小さなゴーストボタン「既定に戻す」。
- **検証エラー**（2 段構え）:
  1. 画面で分かる規則（名前の長さ・空白と @・自発活動の間隔 5 分以上・スキル名の形）は、その入力の下にエラー文。初回は入力欄を離れたときか送信したときに出し、以後は打つたびに更新する（打ち始めから赤くしない）。
  2. 保存で返ってきた `CommandError`（code = `validation` / `conflict`）は、**どの入力のことか分かればその入力の下に**出す（例: 名前の重複 → 名前の欄）。分からなければ、ダイアログ本文の先頭にエラーの帯（`--danger-soft` の面・⚠・本文 primary、`role="alert"`）を出す。どちらの場合も入力内容は消さず、最初のエラーの入力にフォーカスを移し、ボタンを「保存」に戻す。
- `validation` 以外の失敗（`storage` / `internal` など）はトースト（§5.12）。

### 5.11 ダイアログ

- 幕: `--bg-overlay` + `--animation-fade`。本体: 浮いている面の公式（`--radius-xl`・`--shadow-lg`）+ `--animation-rise`、`--surface: var(--bg-elevated)`。幅は `--dialog-width-sm`（確認・チャンネル作成）/ `-md`（設定）/ `-lg`（エージェント編集）、高さは画面 − 64px まで（本文だけスクロール）。
- 見出し部: 上 `--space-6` 左右 `--space-6`（右は閉じるボタンのぶん `--space-5`）下 `--space-4`。タイトル `--text-lg` bold、説明 `--text-md` secondary（上に `--space-1`）、右上に閉じる（アイコンボタン）。
- 本文: 左右 `--space-6`、入力の間 `--space-5`。区画の見出しは小見出しのラベル（`--text-sm` semibold muted `--tracking-wide`）。
- 足元: `--space-5 --space-6 --space-6`、右寄せで［副］［主］。補助操作（「スキルを編集…」）と削除は左端（`margin-right: auto`）。本文がスクロールできるときだけ本文の上下に区切り線（`background-attachment: local` の覆いで、端まで来たら線が消える。Dialog.module.css の `.body`）。
- Esc で閉じる・フォーカスを閉じ込める・開いたら最初の入力にフォーカス・閉じたら開いたボタンに戻す。1 行の入力で Enter は送信。
- **エージェント作成**: 最初に**テンプレートを選ぶ**（§5.9 のテンプレートのカード）。選ぶと下の入力に既定値（タグ・担当・得意分野・振る舞い・権限・自発活動）が入る。何か入力したあとで別のテンプレートを選んだときだけ、カードの下に「入力した内容は、選んだテンプレートの値に置き換わります」（`--text-sm` muted）と出す。作成後のエージェントはテンプレートと結びつかないので、編集画面にはテンプレートの選択を出さない。
- **エージェント編集**: 左に**プレビュー**（`--preview-width`、`--bg-app` のカード、`--radius-lg`）: アバター 64px・名前（`--text-xl`）・タグの札（全部、色は §2）+ BackendTag・担当・口調・振る舞いの要約（中立の線の札で「最初に受ける」「相談相手」「割り振り」「自分から動く」のうち当てはまるもの）・危険な権限の札（§6.3）。編集すると即座に変わる。右に入力の区画: 基本（名前・アバター・個人色・タグ）/ 人格（担当・得意分野・性格・口調）/ 振る舞い / 頭脳（バックエンド・モデル・推論の深さ・詳細設定）/ できること / 自発活動 / スキル。区画は小見出しで区切る。
- **タグの入力**: 札を並べた入力欄（見た目はテキスト入力）。Enter・読点・カンマで札にし、札は §2 の色、× で外す。先頭の札の前に小さく「区分」（`--text-sm` muted）を置き、ヘルプ「先頭のタグがサイドバーの区分になります」。並べ替えはドラッグか、札のメニューの「先頭にする」。8 個に達したら入力欄を無効にして「タグは 8 個までです」。
- **確認ダイアログ**（削除）: タイトルで対象と操作を言う「ギア を削除しますか？」、本文で結果を言う（何が残り、何が消えるか、取り消せるか）。ボタンは［キャンセル］［削除する（危険・確定）］。初期フォーカスはキャンセル。

### 5.12 トースト・ツールチップ

- **トースト**: 右下（`--space-4` 内側）に積む。幅 `--toast-width`、浮いている面の公式、`--animation-rise`、最小 40px。先頭に 16px のアイコン（完了 `--success` のチェック / 失敗 `--danger` の三角）、文 `--text-md`、右に操作（ゴースト小「再送信」など）。完了は 4 秒で消える。失敗は閉じるまで残す（`role="alert"`）。

### 5.13 タスクカード（割り振り）

マネージャー（`canDelegate`）の発言に `delegationId` があれば、その発言の下に割り振り（`Delegation`）の進み具合をカードで見せる。`delegation-changed` で開いたまま更新する。

- **位置**: 発言の本文の下（本文の列、`margin-top: --space-2`、`max-width: var(--measure)`）。本文の ```tasks ブロックは表示しない（同じ内容をカードが持つ）。
- **器**: `--bg-panel` の地・`1px solid var(--border-subtle)`・`--radius-lg`・`overflow: hidden`。浮かせない（影なし。ダイアログやポップオーバーと区別する）。`container-type: inline-size`（狭いときの組み替え用）。
- **見出しの行**（`--space-2 --space-3`、最小 `--control-lg`）: 左に「割り振り」（`--text-sm` semibold）+ 進み具合「3 件中 1 件完了」（`--text-sm` muted・tabular。失敗があれば「· 失敗 1」）。右に全体の状態の札（`--badge-height`、下の表）。
- **進み具合の棒**: 見出しの下に、サブタスク 1 件 = 1 区切り（`display: flex; gap: 2px`、高さ `--space-1`、各区切り `--radius-full`、左右 `--space-3`・下 `--space-2`）。色は状態の色。作業中の区切りだけ `animation: var(--animation-glow)`（形を変えずに呼吸する）。
- **サブタスクの行**（`<ol>`、行の間に `--border-subtle`、内側 `--space-2 --space-3`）: `[状態の印 16px][アバター 20px][名前 semibold／その下に指示][状態の言葉]` の格子。指示は `--text-sm` secondary・`white-space: pre-line`・3 行まで（`-webkit-line-clamp: 3`、全文はツールチップ）。失敗・中止の理由（`note`）は指示の下に状態の色で 1 行。並びは tasks ブロックの順のまま（状態で並べ替えない）。

| サブタスク | 印 | 言葉（色） | 棒の区切り |
|---|---|---|---|
| pending 待機中 | 灯の輪郭（順番待ちの灯） | 待機中（muted） | `--bg-active` |
| running 作業中 | **灯（呼吸する）**、名前を primary に | 作業中（`--accent-text`） | `--activity` + `--animation-glow` |
| done 完了 | チェック（`--success`） | 完了（`--success`）+「結果を見る」 | `--success` |
| failed 失敗 | 三角（`--danger`） | 失敗（`--danger`）+ 理由 +（エラー発言があれば「エラーを見る」） | `--danger` |
| cancelled 中止 | 横線（muted）、指示も muted | 中止（muted） | `--border-strong` |

| 割り振り全体 | 右上の札 | 足元（`--space-2 --space-3`、上に `--border-subtle`） |
|---|---|---|
| running | 灯 +「進行中」（中立: `--bg-active` / `--text-secondary`） | なし |
| reporting | 灯 +「まとめ中」（中立） | 灯 +「**カナメ** がまとめを書いています…」（動作中表示と同じ文法） |
| done | チェック +「完了」（`--success-soft` / `--success`） | 「まとめを見る」。まとめがなければ「まとめはありませんでした」（muted） |
| cancelled | 「打ち切り」（中立・muted） | 「打ち切りました」（muted）。決着していなかった行は中止になる |

- **結果への導線**: 「結果を見る」「エラーを見る」「まとめを見る」はリンクの姿の小さなボタン（`--text-sm`、下線）。押すとその発言までスクロールし、行を一度だけ光らせる（地を `--accent-soft` にして `--duration-slow` で戻す。動きを減らす設定では色だけ）。逆向きには、結果の発言の見出しに「↩ 割り振りの結果」、まとめの発言に「割り振りのまとめ」の中立の線の札を付け、押すとカードへ戻る。
- **動き**: 状態が変わったら印・色を `--duration-normal` で入れ替える。新しいカードは `--animation-fade`。呼吸するのは作業中の灯と区切りだけ（カード全体を光らせない）。
- **狭いとき**（`@container (max-width: 420px)`）: 状態の言葉を指示の下に回す。
- **読み上げ**: `<section aria-label="割り振り（3 件中 1 件完了）">`。進み具合の文は `aria-live="polite"`。状態は必ず言葉でも出す。
- 完了したカードは畳んでもよい（見出しと「まとめを見る」だけにし、「内訳を見る」で開く）。既定は開いたまま。

## 6. 状態を伝える画面

### 6.1 ランナー状態のバナー（`Snapshot.runtime`）

窓の最上部、3 列の上に全幅で出す帯。重ねずに中身を押し下げる（シェルを `grid-template-rows: auto 1fr` に）。高さ `--banner-height`、左右 `--space-4`、`--text-sm`、下に線。

| state | 見た目 | 文言 | 操作 |
|---|---|---|---|
| `starting` | 地 `--bg-panel`、灯の輪郭（順番待ちの灯）。文は secondary・regular（知らせるだけなので太字にしない） | 「エージェントの実行環境を起動しています…」 | なし |
| `unavailable` | 地 `--danger-soft`、線 `color-mix(in srgb, var(--danger) 30%, transparent)`、⚠ `--danger` | 「**エージェントを動かせません** — {runtime.message}」（太字は primary、理由は secondary・1 行で …、全文はツールチップ） | 右端に［再起動］（副・小 → `restart_app`） |
| `ready` | 出さない | – | – |

- 起動直後の一瞬（1.5 秒未満）の `starting` では出さない（毎回のちらつきを防ぐ）。
- `unavailable` から `ready` に戻ったらバナーを消し、トースト「実行環境の準備ができました」。
- `unavailable` の間も入力欄は使える（発言は保存される）。プレースホルダを「いまはエージェントが返答できません（実行環境が止まっています）」に変える。

### 6.2 バックエンドの状態（`BackendInfo.status` / `statusMessage`）

| status | 札の文言 | 札の色 | サイドバーの行 |
|---|---|---|---|
| `ready` | （BackendTag だけ） | 線の札（中立） | ふだん通り |
| `needs_auth` | 「{id} · ログインが必要」 | `--warning` の文字・`--warning-soft` の地・`color-mix(in srgb, var(--warning) 40%, transparent)` の線 | 名前を `--text-muted` に。ツールチップに statusMessage |
| `unavailable` | 「{id} · 使えません」 | 同じ形で `--danger` 系 | 同上 |

- 札は BackendTag と同じ形（高さ 18px・等幅の id）に、状態の言葉を続ける（`--text-xs` だと日本語が潰れるので **状態の言葉だけ `--text-sm` の本文書体**）。サイドバーでは名前を先に縮めて、札は削らない。
- **編集画面**: バックエンドのセレクトの下に状態の行: 準備 OK は「● 準備 OK」（`--success`）、それ以外は ⚠ + 「ログインが必要です」/「使えません」（色は上の表）+ 改行して statusMessage（secondary、`codex login` のようなコマンドは `<code>`）+ 右に［再確認］（副・小 → `refresh_backends`）。押したら「確認中…」で無効にし、`state-changed` で戻す。
- **設定ダイアログ**: 「バックエンド」区画に全バックエンドを並べ（label・id の札・状態・statusMessage）、区画の右上に［すべて再確認］。
- **［ログイン］**: `canLogin` で `needs_auth` のバックエンドは、状態の行の［再確認］の左に主ボタン（sm）の［ログイン］を出す。押すとログインの窓とブラウザが開き、窓が閉じるまでボタンは「ログイン中…」で無効、案内は「開いた窓とブラウザでログインを進めてください。終わると自動で状態が変わります。」に差し替える。ログインできなかったらトーストで理由を出す。
- メンションの候補とメンバーパネルの行でも、ready でない相手には同じ札を出す。

### 6.3 振る舞いと権限（エージェント編集）

**振る舞い**（区画の見出し「振る舞い」）
1. 「メンションのない発言には」: 4 択のラジオカードを 2×2 に並べる（`unmentioned`）。

| 値 | 名前 | 説明 |
|---|---|---|
| `lead` | 最初に受ける | メンションのない依頼は、まず自分が受けます。いるあいだ、ほかのメンバーは答えません。 |
| `answer` | 答える | メンションがなくても答えます。 |
| `fallback` | 他にいなければ答える | 最初に受ける人も答える人もいないときだけ答えます。 |
| `ignore` | 答えない | 呼ばれたときと、割り振られたときだけ話します。 |

2. 「相談相手になる」（`consultable`）: スイッチの行。説明「ほかのエージェントに @ で呼ばれたら、チャンネルの外からでも参加して答えます。」
3. 「タスクを割り振れる」（`canDelegate`）: スイッチの行。説明「依頼を分けて、ほかのメンバーに割り振れます。結果がそろったら、まとめて報告します。」
4. 自発活動は別の区画（「自分から動く」のスイッチと間隔・投稿先）。

**できること**（権限 7 つ）
1. 7 つのスイッチを 1 枚のリストに並べる（`--border-strong` の枠・`--radius-md`、行の間に `--border-subtle`、各行 `--space-3 --space-4`）。行 = ラベル（semibold）+ 説明（`--text-sm` secondary）+ 右にスイッチ。

| 権限 | ラベル | 説明 |
|---|---|---|
| webSearch | Web 検索 | Web を検索して、最新の情報を探します。 |
| webFetch | Web ページを読む | URL を開いて、ページの中身を読みます。 |
| readFiles | ファイルを読む | 作業フォルダ（と相談元の作業フォルダ）のファイルを読みます。 |
| writeFiles | ファイルを書く | 作業フォルダにファイルを作り、書き換えます。 |
| writeAnywhere | 作業フォルダの外にも書く | このパソコンのどこのファイルでも読み書きします。「コマンドを実行」も許せば、PATH などの Windows の設定も変えられます。ソフトのインストールや、ほかのフォルダにあるプロジェクトの作業に使います。 |
| runCommands | コマンドを実行 | 作業フォルダで npm や git などのコマンドを実行できるようにします。 |
| skills | スキルを使う | 登録したスキル（手引き）を読んでから答えます。 |

2. **writeAnywhere と runCommands は危険**: オンにすると行全体が注意の姿になる。枠 `color-mix(in srgb, var(--warning) 50%, transparent)`、地 `--warning-soft`、スイッチの溝は `--warning`・つまみは `--bg-elevated`（金ではなく柿にして「普通のオン」と区別する）、説明の下に注意書き（⚠ + `--warning` の文字、`--text-sm`）。writeAnywhere は「このパソコンのどのファイルでも書き換えや削除ができるようになります。Windows やほかのアプリの設定、このギルドのデータも例外ではないため、任せられる役割のエージェントにだけ許可してください。」、runCommands は「コマンドはこのパソコンの上で、あなたと同じ権限で動きます。ファイルの削除や外部への送信もできてしまうため、任せられる役割のエージェントにだけ許可してください。」確認ダイアログは出さない（行の中の注意書きで十分。毎回の確認は読まれなくなる）。
3. バックエンドの `capabilities` に無い権限はスイッチを無効にし、説明の下に「このバックエンドでは使えません」。
4. バックエンドの組み合わせの規則（`permissionRules`）に合わないと保存で `validation`（field `permissions`）が返る。リストの直下にエラー文を出す（§5.10）。
5. スイッチの `aria-describedby` に説明と注意書きの id を結ぶ。
6. プレビューのカードにも、危険な権限を `--warning` の小さな札で出す（例:「コマンド実行: 許可」）。

### 6.4 削除済みエージェントの過去の発言

- アバター: `filter: grayscale(1); opacity: 0.5;`（形は角丸のまま）。
- 見出し: 名前は `--text-secondary`、続けて「（削除済み）」（`--text-sm` muted）、タグの札と BackendTag は出さない、時刻はふだん通り。
- 本文はふだん通り（内容の価値は変わらない）。名前を押しても何も開かない。
- 他の発言の中のその人へのメンションは、既定のチップ（`--mention-bg`）で出し、ツールチップ「削除済みのエージェント」。

### 6.5 復旧画面（`get_boot_status` が `recovery`）

アプリ全体の代わりに出す。地 `--bg-sidebar`、中央にカード（`--bg-app`・`--border-subtle`・`--radius-xl`・`--shadow-lg`、幅 `--dialog-width-md`、内側 `--space-10 --space-8 --space-8`）。

1. **消えた灯の紋**（48px、線 muted・灯 `--border-strong`）— ギルドの灯が落ちている。
2. 小見出し「データフォルダを開けませんでした」（`--text-sm` semibold muted `--tracking-wide`）。
3. 見出し（理由ごと、`--text-xl` bold）と説明（`--text-md` secondary、`--leading-normal`）。
4. **場所**: ラベル「場所」+ パス（`--font-mono` `--text-sm`、`--bg-sunken`・`--radius-md`・`--space-2 --space-3`、折り返し可）+ 右に［フォルダを開く］（ゴースト小 → `reveal_data_dir`。missing のときは出さない）。
5. **3 つの行動**: おすすめ 1 つを主ボタン（全幅）、残り 2 つを副ボタンで横に並べる。下に「既定の場所に戻しても、いまのフォルダのデータは消えません。」（`--text-sm` muted）。いまの場所が既定なら「既定の場所に戻す」は無効にし、ツールチップ「いまの場所が既定です」。
   - 再試行 → `restart_app` / 別のフォルダを選ぶ → `choose_folder` のあと `change_data_dir(path, 'open')` / 既定の場所に戻す → `change_data_dir(defaultDataDir, 'open')`。`change_data_dir` が失敗したら、ボタンの下にエラーの帯（§5.10）。
6. `<details>`「詳しい情報」に `BootStatus.message`（等幅・muted）。

| reason | 見出し | 説明 | おすすめ |
|---|---|---|---|
| `missing` | データフォルダが見つかりません | 設定されている場所にアクセスできません。外付けドライブやネットワーク上の場所なら、つないでから再試行してください。 | 再試行 |
| `locked` | AIギルドがすでに起動しています | 同じデータフォルダを使う AIギルドがもう 1 つ動いています。そちらを閉じてから再試行してください。 | 再試行 |
| `newer_version` | 新しい版のデータです | このフォルダは、より新しい AIギルドで保存されています。データを守るため、この版では開きません。アプリを更新するか、別のフォルダを選んでください。 | 別のフォルダを選ぶ |
| `foreign` | AIギルドのデータフォルダではありません | このフォルダには AIギルド以外のファイルがあります。大事なファイルを守るため、このフォルダは使いません。 | 別のフォルダを選ぶ |
| `corrupt` | データを読み込めませんでした | データベースが壊れている可能性があります。元のファイルには手を加えていません。 | 既定の場所に戻す（既定なら 別のフォルダを選ぶ） |
| `not_writable` | このフォルダに書き込めません | 書き込む権限がありません。フォルダの権限を確かめるか、別のフォルダを選んでください。 | 別のフォルダを選ぶ |

### 6.6 システム発言と、画面に出さない注記

- 画面に出すのは Rust が保存するシステム発言だけ: 「停止しました」「{名前} がチャンネルに参加しました」「AI 同士の往復が上限に達したので止めました。続けるにはメンションしてください。」「{名前} はこのチャンネルにいないため、メッセージは届きませんでした」「いま返答できるエージェントがいません（…）」「{名前…} には割り振れませんでした（見つからないか、自分自身です）」と割り振りの件数の上限の告知。見た目は §5.4 のシステム発言で統一する（割り振りの進み具合そのものはシステム発言ではなくタスクカードで見せる）。
- **「{名前} は回答しませんでした」「{名前} は失敗しました」は return ジョブの注記として呼び出し元のエージェントのプロンプトに入るだけで、画面には出さない**（UI で作らない・推測して出さない）。
- 時間切れ（「時間切れで中断しました（15分）」）はエージェント名義の kind=error なので、エラー発言として出る。

## 7. 空の状態

形: 中央に縦積み（最大幅 24em）— 消えた灯の紋（44px、muted）→ 見出し（`--text-xl` bold）→ 説明（`--text-md` secondary、`--leading-normal`）→ 主ボタン（あれば 1 つ）。

| 場所 | 見出し | 説明 | 操作 |
|---|---|---|---|
| チャンネルが 1 つもない | 最初のチャンネルを作りましょう | 話題ごとにチャンネルを分けると、エージェントが文脈を取り違えにくくなります。 | ＋ チャンネルを作成 |
| 発言のないチャンネル（チャンネルのはじまり） | #{名前} へようこそ | {話題}　ここが #{名前} のはじまりです。@ でエージェントに呼びかけてみましょう。 | – |
| サイドバーにエージェントがいない | （区画を出さない） | – | 一覧の下の［＋ エージェントを追加］ |

## 8. マイクロコピー

### 声

ギルドの受付係。丁寧で短く、少しだけ温かい。冒険者ごっこはしない（「冒険者よ！」「クエスト」は使わない。「迎える」「仲間」程度のさりげない言葉だけ）。

### 規則

1. 文は「です・ます」。ボタン・見出しは名詞か動詞で短く（「チャンネルを作成」「保存」「停止」）。
2. ボタンは結果を言う。確認のボタンに「OK」「はい」は使わない（「削除する」「既定の場所に戻す」）。
3. 主語は名前。「エージェントが」ではなく「ハル が」。名前のあとは半角スペース＋助詞（Rust のシステム発言と同じ。「ハル が考え中…」）。
4. エラーは「何が起きたか → 次にどうすればいいか」。責めない。技術用語や英語のエラー文を最初に出さない（詳細は 2 行目か「詳しい情報」へ）。
5. 確認ダイアログは、何が残り・何が消え・取り消せるかを書く。
6. 省略は「…」（U+2026）1 文字。「...」にしない。
7. 数字は半角（「3 件」「15 分」）。和欧間の空きは global の `text-autospace` に任せ、文面には手で入れない（Rust 由来の文面はそのまま）。
8. 名前やチャンネルは「#ロビー」「ギア」とそのまま。かぎかっこは入力値を引用するときだけ（「『ギル』に一致する…」）。
9. 感嘆符は挨拶とエージェント本人の発言だけ。UI の文言には使わない。
10. 説明文は「〜できます」「〜します」で。「〜してください」を並べない。

### 文例集

| 場面 | 文言 |
|---|---|
| 入力欄 | #ロビー へメッセージ（@ で呼びかけ） |
| 動作中 | ハル が考え中… / ハル が Web検索中: 〜 / ハル ほか 2 人が作業中 |
| ヘッダー | ハル、ギア が作業中 · 待機 1 ／［停止］ |
| ランナー | エージェントの実行環境を起動しています… ／ エージェントを動かせません — {理由} ［再起動］ ／ 実行環境の準備ができました |

### テンプレートの説明（`AgentTemplate.description`。文面は Rust の guild-domain が持つ）

**声**: 受付係が「この人はこういう人です」と紹介する調子。
- 1 文目で、してくれること。2 文目で、既定の振る舞いのうち使う人が知っておくべきこと（誰が先に答えるか・何をしないか）。
- 主語は書かず「〜します」で終える。60 字まで（カードで 2 行に収まる）。
- 設定の内部の言葉（unmentioned・consultable・権限の名前）を使わず、起きることで言う。役を演じる口調（「任せてください！」）にしない。

| テンプレート | 説明の文案 |
|---|---|
| 作業者 | 頼まれた作業を、手を動かして進めます。メンションがなくても答えます。 |
| 専門家 | 得意分野の相談とレビューに答えます。ほかのエージェントに呼ばれると参加します。 |
| マネージャー | 依頼を分けて、適任のメンバーに割り振ります。結果がそろったら、まとめて報告します。 |
| 調査係 | Web で調べて、出典つきで要点をまとめます。ファイルは書かず、コマンドも使いません。 |
| 書記 | 議論をときどき要約して、決まったことと残った論点を書き残します。 |
| 批判役 | 案の弱点やリスクを、あえて率直に指摘します。呼ばれたときだけ話します。 |
| エンドユーザー役 | 初めて使う人の目線で、感想と困りごとを伝えます。呼ばれたときだけ話します。 |

振る舞いの名前と説明は §6.3 の表、権限の名前と説明も §6.3 の表を使う。

## 9. アクセシビリティ

- コントラスト: 文字はすべて 4.5:1 以上（ホバー・選択中の行の上を含む。ダーク・ライトとも確認済み）。フォーカスの輪は面に対して 3:1 以上。
- 色だけに頼らない: 人 / AI は形、役割は札の文字（タグ名）、状態は文言とアイコンを必ず添える（タスクカードの状態も言葉で出す）。
- キーボード: すべての操作に届く。フォーカスの輪を消すなら同等の代わりを置く。メンション候補とセグメントは矢印キーで動かす。
- 矢印キーで選ぶ一覧（メンション候補・性格と口調のプリセット）は、**マウスを動かしたときだけ**ホバーで選択を移す（`mouseenter` ではなく `mousemove`）。一覧が開いたりスクロールしたりして、止まっているマウスの下に項目が来ただけでは移さない。キーボードで選んだ項目が止まっているマウスに奪われ、Enter で別の項目が決まってしまうのを防ぐ。矢印キーで動かしたときは、選んだ項目が見えるところまで一覧をスクロールする（ホバーで選んだときはスクロールしない）。
- 当たり判定は 24×24px 以上（アイコンボタンは 28px）。
- 読み上げ: アバターは装飾（`aria-hidden`、名前は隣の文字で）。動作中表示は開始・終了だけ `aria-live="polite"`。エラーの帯と失敗のトーストは `role="alert"`、完了のトーストは `role="status"`。
- 動き: 灯の呼吸は「視差効果を減らす」で止まる（global が処理）。

## 10. CSS Modules の実装メモ

**する**
- 値は必ずトークン。足りなければ自分で値を書かず、トークンを足してもらう（このファイルの §3.8 に追記）。
- 状態は属性で表す: `data-status="needs_auth"`、`data-state="running"`、`aria-current="page"`、`aria-selected`、`aria-pressed`、`aria-invalid`、`aria-checked`。CSS はそれを見る。
- 個人色は style 属性でローカル変数として渡す（`style={{ '--avatar-color': agent.color }}`）。
- 役割の色も style 属性で組み立てて渡す（値で分岐しない）: `style={{ '--tag-fg': `var(--kind-${accent}, var(--kind-neutral))`, '--tag-bg': `var(--kind-${accent}-soft, var(--kind-neutral-soft))` }}`。accent が null なら `--kind-neutral` だけを渡す。
- 面を持つ容器では `--surface` を上書きする。
- アニメーションは `var(--animation-*)`。
- 高さのある部品（ボタン・入力・行）は `--control-*` / `--row-height` で高さを固定し、上下の padding で高さを作らない（日本語と英数字で高さがずれない）。
- **枠を指定した入力欄は `:focus-visible` を自分で書く**: global の入力欄のフォーカスは `:where()`（詳細度 0）なので、モジュールの `border` 指定に負けて枠の色が変わらない。`.control:focus-visible:not(:disabled) { border-color: var(--focus-color); box-shadow: 0 0 0 2px var(--focus-glow); }` を hover の後ろに置く。
- 札（タグ・バックエンド・自発・割り振りの状態）は `block-size: var(--badge-height)` で高さをそろえる（見出しの行で札が並んだときに上下がずれない）。

**しない**
- `#fff` や `rgba(...)`、`13px` などの生の値（`1px` の線・`50%` などの比率は可）。
- 個人色を文字色に使う。バックエンドに色を付ける。
- 自前の `@keyframes` で灯を作る（呼吸の速さと見た目がばらける）。
- `box-shadow: var(--focus-ring)` を部品ごとに付ける（global の輪に任せる）。
- 日本語に `--text-xs`。
- 「待機中」「問題ありません」などの、何もない状態を知らせる文。

**よく使うレシピ**
