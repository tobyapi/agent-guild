# 多言語対応

表示とエージェントの会話は、日本語・英語・簡体字・繁体字・韓国語から選べる（`Language` = `ja` / `en` / `zh-Hans` / `zh-Hant` / `ko`）。
初回起動の初期設定と設定ダイアログの「言語」で選ぶ。

## 言語の保存と伝わり方

- 正は settings.json の `language`（マシンごとの好み。データフォルダにも DB にも入れない）。ない場合（言語の設定がなかった版から上げた人）は日本語として扱う。
- `get_boot_status` が `BootStatus.language`（保存した言語。なければ null）を返す。React は保存した言語、初回起動なら OS の言語（`navigator.languages`。合うものがなければ英語）、どちらでもなければ日本語を使う。
- React は選んだ言語を localStorage にも覚え、起動中の画面（起動の結果が届く前）も前回の言語で出す。
- 言語を変えると `set_language` で settings.json に保存する。Rust は同じ値をプロセスの「いまの言語」にし、ランナーにも `setLanguage` を送る（ランナーの起動時は環境変数 `GUILD_LANGUAGE`）。
- 初期設定の「はじめる」では、選ばずに OS の言語のままでも保存する。

## 何がその言語になるか

- **画面の固定の文字列**（React）: feature ごと（や shared の部品ごと）の翻訳表から引く。
- **Rust が作る文字列**: システムのお知らせ（作った時点の言語で発言として保存する。あとで言語を変えても、保存済みの発言は書き換えない）・エラーの文面・テンプレートの名前と説明・復旧モードの理由など。
- **ランナーが作る文字列**: 実行中の表示（「Web検索: …」など）・バックエンドの状態の説明・設定項目の名前・エラーの文面。
- **エージェントの会話**: プロンプトに「この言語で書く」という指示を入れる（日本語のときは入れない）。システムプロンプトの本文は日本語のまま。
- テンプレートの表示名・説明と、作成時に入れる担当・得意分野・タグは、いまの言語のもの。役割は先頭タグで決まるので、どの言語の表示名のタグでも同じ役割になる（`AgentTemplate.roleTags` に全言語の表示名がある）。
- 利用者が入力したもの（名前・人格・スキル・発言）と、保存済みのデータは翻訳しない。初回起動時に作られる初期データ（最初のチャンネルとエージェント）も日本語のまま。

## React の翻訳表

```
src/features/<feature>/i18n/
  ja.ts       export const ja = { key: '文言', withParam: '{name}さん' };   日本語（キーの正）
  en.ts       export const en: Messages<typeof ja> = { ... };            ほかの言語は同じキーをすべて持つ（型で検査）
  zhHans.ts, zhHant.ts, ko.ts
  index.ts    export const t = createTranslator({ ja, en, 'zh-Hans': zhHans, 'zh-Hant': zhHant, ko });
```

- 文言の `{name}` は `t('key', { name })` で置き換える。数で形が変わる文言（英語の単数・複数など）は、値を `({ count }) => ...` の関数にしてよい（ほかの言語は文字列のままでよい）。
- 表が大きくなったら（どのファイルも空行を除いて200行未満）、`i18n/<まとまり>/ja.ts` のように分けて、まとまりごとに `t` を作る。
- `t()` は描画の中（か、描画やイベントから呼ばれる関数の中）で呼ぶ。モジュールの読み込み時に訳した文字列を定数に入れない（言語を変えても変わらない）。選択肢の表などは、キーを持たせて描画のときに引くか、関数にする。
- 言語を変えると `App` が描き直され、その下の部品の `t()` も新しい言語で引かれる。`useMemo` などで訳した文字列を覚えるときは、`useLanguage()` を依存に入れる。
- テストはいまの言語が日本語のまま動く（モックの既定の言語も日本語）。ブラウザでは `?mockLang=en` で言語を指定して起動できる。
