# Ollama の作業ツール

DeepSeekを含むローカルの会話モデルに、ファイルの読み書き・一覧、コマンド実行、スキル参照、途中投稿を提供します。モデルのネイティブツール対応は不要です。OllamaのJSON形式出力で操作を1件ずつ受け取り、アプリが検査・実行した結果を返します。文章中のコードブロックは実行しません。

## 利用条件と権限

- モデルの推論は従来どおり `127.0.0.1:11434` のOllamaで行います。操作機能のためのOpenAI認証やAPI呼び出しはありません。
- コマンドにはCodex CLI 0.167以降の `codex sandbox` が必要です。CLI未導入・隔離失敗時に、無制限のシェルで再試行しません。
- バックエンドを再確認すると、既存の役割定義から実効権限が計算されます。作業者は範囲外への書き込みも含む権限、ほかの役割はそれぞれの固定権限です。権限の計算自体は既存のRust/React共通ルールを使います。
- ファイルツールはパス・権限・途中のシンボリックリンクを検査し、ハードリンクの変更も拒否します。管理領域には書き込みません。MEMORY.mdだけは既存仕様に合わせて権限に関係なく読み書きできます。
- コマンドはwriteFilesなしならread-only、writeAnywhereなしならworkspace-write、writeAnywhereありならdanger-full-accessです。後者にはwriteFilesとwebFetchが必要です。一時フォルダを追加の書き込み先として許可しません。
- コマンドによる読み取りはCodexと同じく範囲外も可能です。webFetchはコマンドのネットワークを許可します。Web検索専用ツールは未対応で、webSearchは無効です。
- スキル本文と付属ファイルは実行ごとに管理領域へ展開し、終了時に削除します。コマンドは60秒、出力は32,000文字、モデルの操作往復は40回が上限です。

## 検証範囲

モックしたOllama応答から実ファイルを作成・読み返すテスト、範囲外・シンボリックリンク・ハードリンク・権限なしの拒否、スキル、途中投稿、キャンセル、回数上限を検証しています。コマンドの設定・秘密の環境変数の除外・隔離失敗時の再試行禁止・中断時のプロセス群停止もテストします。

2026-11-11に元リポジトリへ適用し、macOSとCodex CLI 0.167.0で指定範囲内のコマンド書き込み成功、範囲外・シンボリックリンク経由・read-onlyでの書き込み拒否、ネットワーク無効時の接続拒否、コマンドのキャンセルを実機確認しました。作業者の範囲外書き込みを許可した場合の成功も確認しています。実Ollamaへの要求をキャンセルした後、後続のファイル操作と結果投稿が出ないことも確認しました。

DeepSeekの実応答でスキル名の引数が欠落する事象を確認したため、JSONの全フィールドを必須にし、使わない文字列は空文字にする形式へ修正しました。実行結果には直前の操作要求も含めます。返答の温度は0です。JSON Schemaをプロンプトにも明示しています（[Ollama公式資料](https://docs.ollama.com/capabilities/structured-outputs)）。修正後の実DeepSeek `deepseek-r1:8b` で、スキル参照、ファイル作成と読み返し、コマンド実行（終了コード0）、途中投稿を確認しました。試験は4件の短い依頼に分け、ディスク上の内容と操作イベントを照合しました。一括依頼では推論が長時間続く場合があり、1回の依頼で全操作を完了することの確認はできていません。

追加の既存ファイル上書き試験では、DeepSeekが相対パスと本文の値を誤り、別パスに空ファイルを作成して読み取りを繰り返す場合や、最終回答のtextを空にする場合がありました。完全なJSON例と本文・相対パスの説明を追加した後、絶対パス・本文・書き込み操作1件を明記した短い依頼では、既存ファイルの上書きと最終回答を確認しました。依頼実行の安定性は保証できません。操作イベントが出たことだけで成功と判断せず、対象ファイルを照合してください。

Windows/Linuxでの実行と配布アプリの画面操作は未検証です。ファイルツールの検査は同時に親ディレクトリを差し替える別プロセスとの競合までOSで封じるものではありません。

実機確認では、隔離した試験用フォルダで「ファイルを作成→読み返す→コマンドで確認」を依頼し、ディスク上の内容と終了コードを照合してください。続いて書き込みを限定した設定で、範囲外・リンク経由の書き込みとネットワーク無効時の接続が拒否されることを確かめます。
