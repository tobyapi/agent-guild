# コマンドの隔離（Windows）

役割がコマンドの実行を許していても、閉じ込められない PC ではコマンドを使わない（role-permissions.md）。Windows では、OS の隔離の中でコマンドを動かす共通の部品（`agent-runner/src/backends/command-sandbox.ts`）を持つ。これを使うのは、Ollama のコマンド、Claude の作業者以外の役割のコマンド、指定フォルダのチャンネルでの Ollama のファイル操作。macOS の Ollama は従来どおり Seatbelt を使う。

## 仕組み

- 隔離の実体は Windows 11 の **MXC（Microsoft eXecution Containers）** の `processcontainer`。Codex CLI が Windows で使っているのと同じ仕組みで、管理者の設定・専用のユーザー・ファイアウォールの規則・フォルダの権限（ACL）の書き換えは要らない。
- 呼び出しには、Microsoft が MIT で公開している [MXC](https://github.com/microsoft/mxc) の実行ファイル `wxc-exec.exe`（Microsoft の署名つき）を使う。npm の `@microsoft/mxc-sdk`（版を固定）に入っているものを、設定の JSON を渡して子プロセスとして起動する。
- SDK 本体（Node に読み込むライブラリ）は使わない。SDK は Node 24 以上とネイティブの部品を要するが、配布版の Node は 22 で、実行ファイルを呼ぶ形なら Node の版に左右されない。別プロセスなので、中断・時間切れ・出力の上限での打ち切りも確実にできる。配布物に入れるのは `wxc-exec.exe` だけ（約 12MB。`scripts/stage-runner.mjs` が Windows 向けにだけ入れる）。
- 使えるかどうかは、ランナーの起動時に `wxc-exec.exe --probe` で確かめる。最も強い段階（`base-container`）で、ACL の書き換えが要らず、「一覧だけ」の許可に対応しているときだけ使う。対応するのは Windows 11 24H2（ビルド 26100.9278）・25H2（ビルド 26200.9278）以降。使えない PC では、コマンドは使わない操作のままになる（通常のシェルへは切り替えない）。

## 閉じ込める範囲

設定は `command-sandbox/policy.ts` が組み立てる。許可した場所だけが見え、ほかは読むことも書くこともできない。

| | 内容 |
|---|---|
| 読み書きできる | 作業場所（書き込みの権限がある役割だけ）と、隔離の中専用のホーム |
| 読み取りだけ | 相談元の成果物・スキルなどの readableDirs、書き込みの権限がない役割の作業場所、道具のフォルダ（PATH にあるもの） |
| 名前の一覧だけ | 上の場所へたどり着くまでの親フォルダの、直下の名前（中身は読めない） |
| 見せない | 親フォルダの直下にある、関係のないフォルダ（下の「親フォルダの一覧と、隠すフォルダ」）。呼び出し側が指定した場所（相談相手の MEMORY.md） |
| 通信 | すべて拒否 |
| 画面まわり | 画面は使える（止めると PowerShell・git・node が起動できない）。クリップボードと操作の注入は禁止 |
| 環境変数 | 秘密らしい名前（`agent-env.ts`）を除いて明示して渡す。Windows に登録された利用者の環境変数は引き継がせない |
| ホーム | `USERPROFILE`・`APPDATA`・`LOCALAPPDATA`・`TEMP` を専用のホーム（管理領域の `command-home`。実行のたびに作り直す）へ向ける |

コマンドは Windows PowerShell の文として実行する（符号化して渡すので、引用符の解釈に左右されない）。出力とファイルの書き出しは UTF-8、時間切れは 30 秒、出力は 32KiB まで、コマンドは 8000 文字まで。スクリプトの実行ポリシーは確かめさせない（`-ExecutionPolicy Bypass`）: 隔離の中ではその確認自体が失敗し、npm のように入口が `.ps1` の道具が動かないため。閉じ込めは隔離が担うので、範囲は変わらない。

## 親フォルダの一覧と、隠すフォルダ

MXC の「一覧だけ」の許可（`enumeratePaths`）は、指定したフォルダの**下の階層すべて**に効く（この PC で確認。1段だけにする設定はない）。親フォルダをドライブの直下まで一覧させるだけだと、同じドライブにあるフォルダの中の名前が、利用者のホームの中も含めてすべて見えてしまう（中身と、ファイルの大きさなどの情報は読めない）。一方で、親フォルダをまったく一覧させないと、git と python は動くが、Node はモジュールを読み込めず（パスを先頭から1段ずつ確かめるため）、npm も動かない。

そこで、親フォルダは一覧させたまま、その直下にあるフォルダのうち、許可した場所へ続かないものを拒否（`deniedPaths`）に入れて隠す（`command-sandbox/siblings.ts`）。見えるのは「親フォルダの直下の名前」だけになり、関係のないフォルダは中の名前も見えない（ほかのエージェントの作業場所・利用者の Documents など）。

- **隠さない場所**: Windows・Program Files・ProgramData とその中（隔離の中から最初から見えていて、プログラムが動くのに要る）。`%LOCALAPPDATA%\Packages`（隔離が自分の置き場に使う。拒否すると、その親フォルダごと確かめられなくなった）。
- **リンク（ジャンクション）は拒否に入れない**: 拒否はリンク先に効く。`Documents and Settings`（Users を指す）などを入れると、必要な親フォルダまで拒否してしまう。リンクの先は、その場所自身の許可・拒否に従う。
- **設定を作ったあとにできたフォルダは隠れない**。隠すのは、コマンドを始める時点で実在するフォルダ。
- **かかる時間**: 隠すフォルダ 1 つにつき約 1 ミリ秒（この PC で、2,400 個で約 2.3 秒。作業場所が一時フォルダの下にあるテストの場合で、通常は数百個）。

決まったプログラムだけを動かすとき（`tools: false`。指定フォルダのファイル操作）は、道具のフォルダも親フォルダの一覧も許さない。許可した場所のほかは名前も見えない。Node には、コードの場所のリンクを解決させない指定（`--preserve-symlinks`・`--preserve-symlinks-main`）を付けて起動する。

## この PC で確かめたこと（2026-11-11、Windows 11 25H2 ビルド 26200.9711）

本物の隔離を使う自動テスト（`command-sandbox.test.ts`・`ollama/windows-command.test.ts`。使えない PC では飛ばす）:

- 作業場所の中は読み書きでき、相談元は読めるが書けない。範囲の外は読むことも書くこともできない。
- 範囲の外のフォルダは、中の名前も一覧できない（利用者の Documents も）。親フォルダの直下の名前だけが見える。
- 作業場所のスクリプト（`.ps1`）を動かせる。
- 外部への TCP 接続はできない。秘密らしい環境変数は渡らない。ホームは専用のもので、利用者の本物のホームではない。
- 書き込みの権限がない役割では、コマンドからも作業場所に書けない。
- 出力が上限を超えたら止まり、中断すると実行中のコマンドも終わる。設定ファイルは残らない。
- Ollama のアダプタを通して、モデルが JSON 操作で頼んだコマンドが隔離の中で動き、結果がモデルへ返る（モデルの応答だけ偽物）。
- 指定フォルダのファイル操作（`ollama/container-file.test.ts`）: 割り当てフォルダの中は読み書き・一覧ができ、範囲の外は読むことも書くことも一覧することもできない。パスの判定のあとで外へのリンクに差し替えられても、リンク先には届かない。ハードリンクのあるファイルと、相談相手の MEMORY.md は断る。

実際の Claude（Haiku。専門家の権限）での通しの実行: ランナー経由で `mcp__guild__run_command` が呼ばれ、作業フォルダへの書き込みと相談元の読み取りができ、範囲の外の読み書きと通信は拒否された。内蔵の Bash は道具の一覧になかった。

手で確かめたこと: 関係のないフォルダを隠した設定で、git（リポジトリの作成）・node（モジュールの読み込み）・npm・python・PowerShell が中で動く。npm は、実行ポリシーを確かめさせない指定を入れるまで、起動時の確認で止まっていた。Codex CLI の従来方式（管理者設定なし）は、通信を環境変数でプロキシに向けているだけで、外部への TCP 接続は成功した。MXC では TCP も DNS も失敗した。

## 使う側

どちらも範囲の決め方は同じ（`command-sandbox/role-command.ts`）: 書けるのは作業場所（書き込みの権限がある役割）、読めるのは作業場所・readableDirs・道具のフォルダ。役割が PC 全体の読み取り（readAnywhere）を許していても、コマンドには広げない（秘密のファイル名の除外をコマンドでは守れないため。広く読むのは、秘密の場所を除けるファイル道具の役目）。

| | 道具 | 時間切れ・出力の上限 | 補足 |
|---|---|---|---|
| Ollama | `run_command`（ネイティブの道具・JSON 操作） | 30 秒・32KiB | 既定では、別のモデル呼び出しで操作を確認する |
| Claude（作業者以外） | `mcp__guild__run_command`（アプリが作る guild サーバーの道具） | 120 秒・64KiB | スキルの展開先も読める。外に影響しないので、操作の確認にはかけない |

Claude の作業者（読み書きも Web もすべて許す役割）は、これまでどおり内蔵の Bash を隔離なしで使う。Claude 内蔵の Bash は隔離の中に入れられない。

## 分かっている制約

- **親フォルダの直下の名前は見える**: 作業場所や道具のフォルダへたどり着くまでの親フォルダ（ドライブの直下・利用者のホームなど）にあるファイルやフォルダの名前を一覧できる。中身は読めず、関係のないフォルダは中の名前も見えない。システムのフォルダ（Windows・Program Files・ProgramData）と `%LOCALAPPDATA%\Packages` の中は、名前を一覧できる。
- **フォルダの並びが違う PC では確かめていない**: 隠すフォルダの決め方は、この PC（ホームが C ドライブ、道具が Program Files と利用者のホームの下）で確かめた。ホームをほかの場所へ移している PC やネットワークドライブでは、道具が動かなくなる可能性がある（その場合もコマンドが失敗するだけで、範囲は広がらない）。
- **PATH にあるフォルダは読める**: 道具として読み取りを許す。PATH に秘密を含むフォルダを入れている場合は、その中身も読める。
- **専用のホームでは動かない道具がある**: 利用者のホームにある設定を前提にする道具（rustup 経由の cargo など）は、そのままでは動かない。git は利用者の設定（名前とメールアドレスなど）を読めないので、コミットには `-c user.name=…` などの指定が要る。
- **Windows PowerShell 5.1 の UTF-8 は BOM つき**で書き出される。
- **作業フォルダの外への書き込み（writeAnywhere）は、まだこの隔離を使っていない**（Windows の Ollama では使わない操作のまま）。指定フォルダのチャンネルでは、ファイル操作だけをこの隔離の中で行う（コマンドとスキルは、どの OS でも使えない）。
- Ollama の実際のモデルを使った通しの実行と、ARM64 の Windows、ビルド番号が下限ちょうどの PC では確かめていない。
