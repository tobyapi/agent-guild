# 発想オペレーター集（Concept Shift v0.1）

この文書は**古典をAI向けに再解釈したオペレーター設計**であり、歴史的著作の原文命令を再現したものではない。主ファイルだけで判断できるときは読まなくてよい。

## 1. `ASSUMPTION_SHIFT` — 前提を動かす

**着想源**：水平思考、論点・定義の問い直し。

1. 問題を定義・対象・役割・時間・因果・順序・媒体に分解する。
2. 本質的でないのに「当然」とされるルールを一つ選ぶ。
3. 反転・除去・交換・時間移動・極端化のうち一つだけ実行する。
4. 変えた世界で必然的に起きることを3つ挙げ、そのうち価値あるものを設計に変える。

**失敗例**：「ゲームにノーツがある」→「ノーツを赤くする」（ルール変更になっていない）。

## 2. `PROBLEM_REFRAME` — 問いを変える

**着想源**：問題の言い換え、類似問題、逆向きに考える発見法。

1. ユーザーの望む結果と、指定された方法を分ける。
2. 目標を保ち、解く問題を逆転・縮小・抽象化・逆算する。
3. 「本当は何を最大化・最小化したいのか」を明文化する。
4. 元の問題では考慮されていなかった解法群を生成する。

**失敗例**：依頼者が本当に守りたい制約まで「思い込み」として破る。

## 3. `CONTRADICTION` — 矛盾を発明の入口にする

**着想源**：TRIZ（技術的／物理的矛盾の解決）。

1. Aを改善するとBが悪化する関係を記述する。
2. 妥協案を第一候補にしない。
3. 時間・場所・対象・条件で要求を分離できないか探す。
4. 両立を可能にする仕組み（分割・動的変更・事前処理など）を具体化する。

**失敗例**：「高速で高品質に」と願うだけでトレードオフを処理しない。

## 4. `STRUCTURAL_ANALOGY` — 異分野の仕組みを移す

**着想源**：シネクティクス、異質な文脈を結び付ける発想（バイソシエーション）。

1. 目的領域を「何を維持し、何を変えるシステムか」で抽象化する。
2. 自然・数学・音楽・スポーツ・社会制度など離れた領域を選ぶ。
3. 見た目や名前でなく、入力→状態遷移→フィードバックの構造を移す。
4. 移植によって旧規則がどう変わるか示す。

**失敗例**：「銀行みたいなゲーム」と名付けただけで、何の仕組みも移していない。

## 5. `CONSTRAINT_REWRITE` — 制約を生成規則に変える

**着想源**：制約を課す文学的実験。

1. 現在の制約を、禁止・義務・順序・リズム・対称性などに分類する。
2. 「何を禁止／必須にすると新しい表現が発生するか」を試す。
3. 制約によって発生する、偶然ではない特徴を見つける。
4. 難しいだけの制約は廃棄。表現上の価値につながる制約を採用する。

**失敗例**：無意味な制限を増やすだけで、作品が貧しくなる。

## 6. `RELATION_RECOMBINE` — 関係を組み替える

**着想源**：組合せ的思考、既存要素の新しい組合せによる発想。

1. 要素A/B/Cに加え「AがBを制御する」など関係Rを抽出する。
2. 要素自体より、関係の向き・強さ・適用タイミング・主体を変える。
3. 変えた関係の下で初めて可能になる設計を考える。

**失敗例**：表面上のキーワードの無作為連結しか行わない。この場合は組合せ的創造であり、変革的とは限らない。

## 7. `ABDUCTIVE_LEAP` — 驚きを説明する仮説

**着想源**：アブダクション（驚く事実を説明する仮説形成）。

1. 現在の枠組みでは奇妙・不自然な現象を置く。
2. それが自然になる「別のルール」の仮説を2〜3個考える。
3. それぞれの仮説が他に何を予測するか確認する。
4. 最も豊かな結果を生む仮説を世界観／設計ルールにする。

**失敗例**：奇妙な出来事を説明しないまま後付け設定を増やす。

## 8. `VALUE_SHIFT` — 成功の定義を変える

**着想源**：概念空間の考え方を発想設計に応用したもの。固有の古典的技法名ではない。

1. 現在の成功指標（速さ、正確さ、勝敗、所有、視聴数など）を明示する。
2. ユーザーの最終目的を損なわない範囲で、別の成功指標を仮定する。
3. 新しい評価関数ならどんな仕組みが優位になるかを逆算する。
4. 自己目的化していないか（何のための価値変化か）を確認する。

**失敗例**：価値の変化によって依頼者の目的を完全に失う。

## 選択のヒント

- 見た目だけ違う案が続く → `VALUE_SHIFT` または `ASSUMPTION_SHIFT`
- 解決方法の違いしか出ない → `PROBLEM_REFRAME`
- 両立不能で停滞している → `CONTRADICTION`
- 常識の内側から出られない → `STRUCTURAL_ANALOGY`
- 既存作品と似る → `CONSTRAINT_REWRITE` と `STRUCTURAL_ANALOGY`
- 不思議な設定が核 → `ABDUCTIVE_LEAP`
