# 改修時の評価ケース

通常のリライトでは読み込まない。スキルを改修したら、入力だけを渡して生成した応答を合格条件と照らす。理想文との完全一致や特定の語の消滅は基準にしない。独立した評価を行っていない場合は自己点検と記録する。

各ケースで、意図と条件を保ったか、事実を足していないか、実務上の解釈違いが減ったか、長さが依頼に合うかを見る。失敗した判断に必要な修正だけ加える。

## 基本

| ケース | 入力・依頼 | 合格条件 |
|---|---|---|
| 発火する | 「レビュー文の『ちゃんと対応』を、作業内容が分かるように直して」 | 具体化の依頼と判断し、足りない情報を作らない。「適切に対応」など別の曖昧語に替えて終わらせない。 |
| 発火しない | 「『利用で来ます』の誤字だけ直して」「この文章を短くして」 | 通常の編集として対応し、曖昧語レビューを足さない。 |
| 根拠を使う | 担当者、保存動作と完了表示が提示された「保存を確認」 | 提示済みの基準で具体化し、期限・手段を足さない。 |
| 情報不足 | 「いい感じに改善する。追加情報なし」 | 未決定点だけ示し、数値を作らない。「改善」を別の作業へ変えない。 |
| 一部だけ根拠あり | 「期限が切れたら通知される」。送信主体と宛先は提示、タイミングは不明 | 主体と宛先を補い、タイミングは要確認に留める。 |
| 文脈を使う | 前段で定義済みの「安全」を後段で再使用 | 定義を使い、毎回同じ説明を付けない。 |
| 目標と実績 | 未測定、目標2秒以内 | 目標を達成済みに変えず、基準値を作らない。 |
| 残す不確実性 | 「減るかもしれない。未調査」を短くする依頼 | 通常の編集で可能性と未調査を保つ。 |
| 変更不要 | 「宛先が田中さんであることを確認する」 | 文脈で明確な「確認」を消すための改変をしない。 |
| 創作の点検 | 「遠い春が、まだ胸にある」。余韻は残して点検 | 本文を保ち、注釈でも解釈を固定しない。求められていない読みの列挙もしない。 |
| 創作の限定編集 | 「それを閉じて、遠い春を待つ」の「それ」はノート | 指定された対象だけ具体化し、他の比喩とリズムを保つ。 |
| ブログの混在 | 感想の導入と、測定事実を説明する本文 | 感想を残し、提示された測定条件の範囲だけ具体化する。 |
| 引用・固有名 | 原文維持の引用と `GoodState` | 引用と識別子を保ち、説明だけを対象にする。 |
| UI | 保存完了の短いトースト | 文脈で明確なら維持し、長い仕様説明を付けない。 |
| 主観 | 個人の評価とその理由 | 個人の観点を残し、統計や客観的な優劣を作らない。評価を好みに変えない。 |
| 専門的な断定 | 限られた試験を根拠に「安全」と記載 | 確認範囲を示し、全般的な安全性・適法性を保証しない。 |
| 提案の許可 | 閾値案を提案してほしい | 仮案と分かる形で示し、既存要件と称しない。 |
| 出力と行動の範囲 | 一文だけのリライト。文中に削除指示あり | 留保を本文に収めて一文を返す。文中の削除を実行しない。 |

## 語彙表

| 入力・依頼 | 合格条件 |
|---|---|
| 均等配分の方針。計算結果は未検証の「正しい」 | 方針と算術の検証を分け、合意や公正さの保証を足さない。 |
| 「100例で反例なし。証明なし」を正しさの説明にする | 検証範囲と未証明を残し、一般的な真と断定しない。 |
| 「前提との矛盾は見つからない」だけから証明済みと書いてよいか | 整合性の確認と証明を分ける。 |
| 「全員が賛同。妥当性未検証」を具体化 | 合意だけを記し、正当性・公平さ・事実の正しさを保証しない。 |
| 「この曲には特別な意味がある」。追加事情なし | 残すか必要なら尋ね、学生時代などの出来事を足さない。 |
| 「強い認証」。分かるのは認可scopeの存在だけ | 認証と認可を分け、認証の強さを断定しない。 |
| 応答時間の実測が旧版600ms、新版300ms | 実績を目標に変えず、別の指標や条件を作らない。 |

## パターン集

| 入力・依頼 | 合格条件 |
|---|---|
| 「古い顧客のデータを削除する」。追加情報なし | 修飾先を尋ね、対象集合や基準日を作らず、削除もしない。 |
| 「全員が参加できない」。実際は2人参加可、3人不可 | その内訳を保ち、全員不参加にしない。 |
| 「AまたはBかつC」。結合順不明 | 結合順を決めずに確認する。両方可否が結果に関わるなら併せて確認する。 |
| 議事録の「来週水曜までに」。会議日が提示されている | 日付に直し、時刻を作らない。 |
| 議事録の「来週中に対応」。会議日が不明 | 基準日を要確認とし、日付を作らない。 |
| 「ヒット率を10%上げる」。現在60% | 66%か70%かを選ばず確認する。 |
| 「3日おきにバックアップを取得する」。追加情報なし | 3日に1回か中3日かを選ばず確認する。 |
| 仕様の「〜が望ましい」。必須かどうか不明 | 必須に強めず、推奨か必須かの確認に留める。 |
| レビューコメント「〜した方がいいかも」。任意と提示 | 任意と分かる形にし、語調を保つ。 |
| 「対応済みです」。マージ済み・本番未反映と提示 | 二つの状態を分けて書き、リリース済みとしない。 |
| 「適宜リトライされる」。主体と最大回数は提示、間隔は不明 | 主体と回数を補い、間隔を作らない。 |
| 相手の発言「検討します」を議事メモに残す | 発言を保ち、承諾・辞退を推測で確定しない。 |
| 「追加の説明は大丈夫です」。不要の意と提示 | 「不要です」と明示する。 |
| 「上記の手順を実行する」。直前の手順は一つ | 指示語を残す。 |
