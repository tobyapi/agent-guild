# 判断が分かれる例

例文の固有名・数値は、その例の入力に与えられた条件だけに有効。別の依頼の既定値にしない。

## 根拠のある具体化

入力: 「QA の佐藤さんが明日、設定画面の保存ボタンを確認。押すと変更が保存され、『保存しました』を表示する仕様。作業指示を具体的にして」

修正文: 「佐藤さんは明日、設定画面で保存ボタンを押し、変更が保存されることと『保存しました』が表示されることを確認する。」

避ける: 「佐藤さんは明日17時までに全ブラウザーの E2E テストを完了する。」時刻、対象範囲、手段を足している。

## 情報が足りない

入力: 「画面をいい感じに改善する。具体化して。追加情報はない」

修正文案: 「画面を改善する（要確認: 対象画面と、利用者が困っている点）。」不足している点だけを示し、「改善」を別の作業に変えない。

避ける: 「一覧画面の表示を200ms以内にする。」画面、指標、閾値を作っている。「適切に改善する」への置換も判断材料を増やさない。

## 目標・実績・不確かさ

入力: 「10万件の一覧を表示する時間は現状未測定。目標は同じ端末で2秒以内。『速くする』を具体化して」

修正文: 「同じ端末で10万件の一覧が表示されるまでの時間を2秒以内にすることを目標とする。現状の所要時間は未測定。」

避ける: 「表示時間を5秒から2秒へ短縮した。」基準値と達成実績を作っている。

入力: 「この変更で離脱が減るかもしれない。まだ調査していない」

判断: 仮説と未調査を保つ。「離脱率が改善した」と断定しない。

## 読みを選ばない

入力: 「『キャッシュヒット率を10%上げる』を目標として具体化して。現在は60%」

修正文案: 「キャッシュヒット率を現在の60%から上げる（要確認: 目標は66%か70%か）。」入力から導ける二つの読みを示し、どちらかに決めない。

入力: 「『古い顧客のデータを削除する』。追加情報なし」

判断: 古いのが顧客かデータかで削除対象が変わり、削除は戻せないので質問する。対象集合や基準日を作らず、削除も実行しない。

## 日時

入力: 「議事録の『来週水曜までに佐藤さんが見積もりを提出』を、後から読んでも分かるように。会議は2026年6月1日（月）」

修正文: 「佐藤さんが2026年6月10日（水）までに見積もりを提出する。」

避ける: 「6月10日（水）17時までに」。時刻を作っている。会議日が不明なら「来週水曜（要確認: 会議日）」とし、日付を作らない。

## 義務の強さ

入力: 「レビューコメント『ここは早期returnにした方がいいかも』。マージ前に必須かどうかが伝わるようにしたい。自分としては任意」

修正文: 「任意の提案です。ここは早期returnにした方がいいかもしれません。」

避ける: 「早期returnに修正してください。」必須に強めている。必須か任意かの提示がなければ、選ばず要確認にする。

## 「正しい」の軸

入力: 「経費の分配は正しい。端数を除いて全員が同額を受け取るという意味。計算の検証はまだ」

修正文: 「経費は、端数を除いて全員に同額を分配する。計算結果は未検証。」

避ける: 「分配額は計算上正しい。」配分の方針と算術の検証を混同している。全員が納得しているとも推測しない。

## 変更不要

入力: 「送信前に、宛先が田中さんであることを確認する。曖昧なところだけ直して」

出力: 「変更不要です。確認の対象と基準が示されています。」

避ける: 「担当者はチェックリストを作成し、宛先確認の証跡を記録する。」元にない手順を足している。

入力: 「保存完了を伝えるトーストは『保存しました』。短いままで曖昧さだけ点検して」

判断: 通知が示す状態は文脈から分かる。処理手順や担当者を足さない。

## 創作・感想・引用

入力: 「詩の『遠い春が、まだ胸にある』を、このスキルで点検して。余韻は残して」

出力: 「変更不要です。このまま残せます。」

避ける: 「『遠い』は思い出の余韻を表しています。」本文を変えなくても、作者が示していない意味を説明で決めている。求められていない別の読みの列挙も要らない。

入力: 「歌詞『それを閉じて、遠い春を待つ』の『それ』はノートを指す。そこだけ伝わるようにして」

修正文: 「ノートを閉じて、遠い春を待つ」。指定された指示対象だけを具体化し、「遠い春」の意味は説明でも決めない。

入力: 「『春が少し近づいた気がする。この更新で表示が速くなった。』事実説明だけ点検して。実際に確認したのは、同じ端末で一覧表示が3秒から2秒になったこと」

修正文: 「春が少し近づいた気がする。この更新後、同じ端末で一覧表示にかかった時間は3秒から2秒になった。」感想は保ち、確認していない画面や環境まで速くなったとは書かない。

入力: 「私には青い案のほうが良い。落ち着いて見えるから。個人の感想として短く整えて」

修正文: 「私には、落ち着いて見える青い案のほうが良いです。」評価と理由を残す。「好き」に替えると好みの告白へ意味がずれる。

入力: 「『ちゃんと確認する』という発言は原文のまま残し、API名 `GoodState` も変えず、その意味の説明だけ整えて」

判断: 引用と API 名は保ち、根拠のある説明だけを編集する。具体化のために改名しない。
