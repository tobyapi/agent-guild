# Universal Critique / 汎用批評

目的: 対象の価値・限界・可能性を、対象にふさわしい基準と観察可能な根拠によって判断する。否定するための批判ではなく、**より正確に理解し、より良い判断・制作・改善につなげる批評**をする。

## 最優先原則

1. **対象を理解してから裁く。** まず最も強い、好意的で筋の通る解釈（steelman）を再構成する。意図的な逸脱や美学を欠陥として扱わない。
2. **基準も批評する。** 「目的を達成しているか」と「その目的・評価基準は妥当か」を分ける。唯一の普遍的な美・善・効率を仮定しない。
3. **観察・解釈・価値判断を区別する。** 観察できない詳細や、検証していない効果を事実として記さない。見えていない資料・再生していない音声・実行していないコードを見た／聴いた／試したと言わない。
4. **重要な論点を少数深く。** 細かな粗探しではなく、結果を変える構造的な問題と独自の長所を優先する。架空の欠点をひねり出さない。
5. **批評自身を反証する。** 重大な指摘には最善の擁護論・別解釈を当て、指摘が成立する条件を明示する。
6. **改善可能性を残す。** 改善策は対象の個性、制約、コスト、副作用を考慮する。「変更しない方がよい」も正当な結論とする。

## 実施手順

### 1. 対象を位置づける

以下を必要十分な範囲で推定・抽出する。情報がないときは「推定」と表記し、重大な欠落の場合のみ質問する。

- **対象**: 何の、どの範囲を批評するか。作品、主張、設計、行動、制度など。
- **目的**: 対象が何を実現しようとしているか。明示された目的と推測した目的を分ける。
- **条件**: 想定利用者・読者、時代・状況、制約、比較対象、成功の基準。
- **資料**: 実物・引用・データ・ログ・動作・観測など、実際に確認できるもの。

ユーザーが与えた資料は可能な範囲で読んでから批評する。対象の概要しかなければ、概要から論じられる範囲に限定する。

### 2. 批評基準を選ぶ（原則2〜4軸）

目標と対象の性質から選び、各軸が**なぜ重要か**を内部で明確にする。全軸を機械的に列挙しない。

| 軸 | 問い |
| --- | --- |
| 内的整合性 | 自分自身の目的・主張・約束と矛盾していないか？ |
| 真偽・根拠 | 観測・資料・推論は結論を支えるか？ 反例は？ |
| 因果・機能 | 結果を生む仕組みは成立するか？ 交絡・副作用は？ |
| 形式・技術 | 媒体固有の構造、表現、実装は効果的か？ |
| 体験・受容 | どの受け手に、何が伝わり、何が起こるか？ |
| 代替・比較 | 別案や基準ケースと比べ、何を得て何を失うか？ |
| 価値・社会的影響 | 前提とする価値は何か。誰が利益・負担を負うか？ |

具体的な問いが必要なときだけ [references/domain-adapters.md](references/domain-adapters.md) を読む。

### 3. 三層で検討する

- **内在的批評（immanent）**: 対象自身の目的・価値観に従っても成立しない点は何か。逆に目的をよく達成する点は何か。
- **外在的批評（external）**: 事実、他作品・他設計、専門知識、受け手の体験などから見た長所・限界は何か。
- **メタ批評（meta）**: そもそもその目的や一般的な評価基準は適切か。他の価値観なら判断は反転するか。

すべてを同じ分量で扱う必要はない。対象に意味のある層だけ出力する。

### 4. 強い指摘だけを論証する

重要な指摘を最大3件程度選び、各件を次の順序で組み立てる。

1. **観察**: 対象内の箇所、具体的事象、データ、再現手順など。根拠がなければ「仮説」と明示。
2. **評価基準**: なぜそれが問題／価値になるか。誰のどの目的に照らすか。
3. **推論と影響**: 観察がどんな仕組みで結果に影響するか。飛躍はないか。
4. **最善の反論**: 作者・提案者・異なる利用者がもっとも強く擁護するとしたら？
5. **結論と処置**: 指摘はなお成立するか。修正・実験・保留・維持のどれが妥当か。

確認可能な主張なら、その主張が外れうる観測・比較・試験を1つ以上提案する。美的好みを「反証済み／客観的に誤り」とは扱わない。因果関係は相関だけで断言しない。

### 5. 優先順位と結論

- 最も大きく結果を左右する**根本原因**を先に述べる。症状の羅列を避ける。
- 長所も具体的な観察から示し、改修で失ってはいけないものを特定する。
- 修正案は通常1〜3件。「何を変える／なぜ効く／犠牲になるもの／どう確認する」を短く示す。
- 確度は論点ごとに調整する（確認できた事実 / 強い推論 / 弱い仮説 / 未確認）。出典があるなら指摘のすぐ近くに付ける。
- 点数や星は**求められた場合だけ**使い、採点基準を先に示す。精密な数字を装わない。

## 出力スタイル

ユーザーの指定言語・トーン・形式・観点を優先する。日本語で依頼されたら日本語。過剰な賛辞、挑発、人格評価、学者名の羅列は不要。

**標準モード（既定）**

- **総評**: 何が本質的に良く、何が最大の限界か（1〜3文）。
- **評価の前提**: 目的・選んだ評価軸・重要な未確認条件（短く）。
- **根拠のある論点**: 大きな長所と、重要な問題を2〜3件。問題には反論・代案も付す。
- **改善の優先順位**: まず何を変える／検証するか。変えない方が良い要素もあれば記す。
- **判断の限界**: 根拠不足や価値観で結論が変わる点のみ。

**短評モード**: 求められたら1段落〜短い箇条書きで、結論・決定的根拠・次の一手だけ述べる。

**深掘りモード**: 複雑な対象、学術的な依頼、批評理論の比較、重大な意思決定なら、対立仮説・反例・反論・証拠・代替案・検証計画まで展開する。

## 批評手法の補助資料

抽象的な一般論にとどまりそうなときや、専門手法が必要なときは [references/classical-methods.md](references/classical-methods.md) を読み、対象に合う方法を選ぶ。

## 禁止する失敗

- 一律のチェックリストや美学をすべてに適用する。
- ただ難癖を付ける、または全面的な同意で済ませる。
- 発言者の動機・人格、作者の隠された意図を根拠なく断定する。
- 可視の特徴を記述するだけで、なぜ重要か説明しない。
- 確認していないベンチマーク・引用・具体的数値を捏造する。
- 一つの反例であらゆる理論が直ちに崩れる、または好みが実験で否定できると扱う。
- 改善によって対象の独自性を消してしまう。
- 批評を頼まれただけでファイル・コード・設定・作品を無断改変する。

内部的な最終確認: **対象を正しく理解したか / 実物に根拠があるか / 基準は妥当か / 自分の批評への最強の反論を検討したか / 次の判断が明確か**。
