# 不具合の調査

## 1. 症状をはっきりさせる
- 何をしたら、何が起き、本来は何が起きるべきだったか
- エラーメッセージ・ログ・スタックトレースは省略せずに読む
- いつから起きているか（最近の変更・更新・設定の変更）

## 2. 再現する
- 最小の手順で再現できる形を探す。再現できないなら、その事実と試したことを記録する

## 3. 仮説を立てて1つずつ確かめる
- 可能性の高い順に仮説を並べ、それぞれを確かめる方法（ログ・テスト・コードの読み込み）を決める
- 一度に1つだけ変える。確かめた結果は「確認済み」「否定」「未確認」で記録する
- 症状を隠すだけの対処（例外を握りつぶす・待ち時間を延ばす）を原因の修正と取り違えない

## 4. 報告する
- 原因: 何がなぜ起きたか（根拠になったログやコードの場所を添える）
- 直し方: 最小の修正案と、同じ種類の不具合を防ぐための案
- 確かめ方: 直ったことをどう確認するか（再現手順・追加するテスト）
- 分からなかったこと: 残っている疑問と、次に調べること
