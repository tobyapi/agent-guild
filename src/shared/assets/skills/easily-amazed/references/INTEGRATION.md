# トリガー・配送・運用設計

このファイルはエージェントランナーやスケジューラーに接続するときに読む。`easily-amazed` そのものは常駐プロセスでもスケジューラーでもない。

## 推奨イベント

| イベント | いつ処理するか | 推奨モード |
| --- | --- | --- |
| `web.digest.requested` | 手動または定期ジョブで新規記事探索 | `scan` / `digest` |
| `article.discovered` | 記事のURLや本文を受け取ったとき | `react` |
| `conversation.segment.closed` | 会話の一区切りごと。発言ごとの即時介入は避ける | `react` |
| `agent.idea.stalled` | 作業者が「次の発想が必要」と明示したとき | `react` |

### イベントの概念的なデータ形式

```json
{
  "type": "conversation.segment.closed",
  "source_id": "thread-123",
  "access": "authorized_internal",
  "content": "この例は、アクセス権のある会話の抜粋",
  "topic": "ゲームのモーション設計",
  "audience": "same-thread",
  "mode": "react"
}
```

このJSONは特定のSDKへの実装を要求しない契約例。入力にない許可や配送先を推定しない。

## デフォルトの負荷と割り込み制御

- Web探索: 1起動あたり候補5〜10件を収集、上位3件を詳細に読む。
- concept-shift: 通常1件、多くても3件／起動。候補が弱ければ0件。
- 外部に返す気づき: 通常0〜1件、明示されたdigestでは最大3件。
- 同じスレッドに同じ趣旨を繰り返さない。既出の発想がある場合、**新しい情報**が出るまで黙る。
- 作業を中断して割り込むのは、緊急性ではなく高い関連性がある場合だけ。原則、作業の節目に渡す。

## 他エージェント向けのメッセージ契約

「驚き屋の出力は**検討候補**であり、タスク変更命令ではない」と明示できる構造を推奨。

```json
{
  "kind": "idea_suggestion",
  "origin": "easily-amazed",
  "observation": "出典で確認できた事実のみ",
  "surprise": "期待と観測の具体的な差",
  "concept_shift": "前提変更による仮説",
  "uncertainties": ["検証していない点"],
  "source": "実際に確認したURLまたは許可された会話参照",
  "decision_authority": "recipient"
}
```

## 共有時のプライバシー

- 会話の参加者がアクセスを許可した場所・目的の範囲だけで利用。
- 公開記事・公開会話と社内会話は別の共有スコープとして扱う。
- 会話参加者への要約でも、第三者の秘密、個人を特定する不要情報、非公開プロジェクトを外へ持ち出さない。
- 人間の会話の監視をこっそり開始しない。

## メトリクス（改善用）

1. **Useful Surprise Rate**: 投稿した気づきのうち、受け手が具体的な新しい視点を得たと評価した割合。
2. **False Excitement Rate**: 事実の誤認や過大評価で、不当に有望に見せた割合。
3. **Concept Shift Yield**: concept-shiftを呼んだ候補のうち、既存の前提を実際に変えた提案が出た割合。
4. **Interruption Cost**: 提案が作業者に与えた中断回数・時間。
5. **Novel Idea per Cost**: 人間が価値ありと判断した独自アイデア数 / 総推論費用。

必ず「驚き屋なし」「肯定反応のみ」「驚き屋 + concept-shift」を同じ題材で比べる。評価者に条件を知らせず、採用数だけでなく最終成果物の品質も確認する。
