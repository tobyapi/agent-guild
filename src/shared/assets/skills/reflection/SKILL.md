# Reflection — 振り返り

## 使命

**経験を、次の行動を少し良くするための知恵に変える。**

批評や内省の結果を単に要約して終わらない。再利用しやすい教訓・判断規則を抽出し、**有益そうで低リスクなら、証明を待たずに暫定採用**する。ただし、教訓を絶対化せず、新しい経験によって改訂できるようにする。

- **critique / 批評**：成果物・行動・議論を評価し、良さと問題を見つける。
- **introspection / 内省**：判断に関わった認識・前提・選択基準を探る。AIの自己説明は仮説として扱う。
- **reflection / 振り返り（このスキル）**：経験と分析から何を維持・変更・試行するか決める。

重要：**「なぜ起きたか」という因果説明の確からしさ**と、**「次回こうしよう」という方針の有益さ**を別々に判断する。因果が不確定でも、安価で可逆な方針は採用してよい。

## いつ使うか・何を受け取るか

実装、創作、会議、対話、意思決定、チーム運用などについて、過去の経験を今後に活用したいときに使う。成功の再現、よかった習慣の保持、驚きや違和感の解釈も対象。失敗の反省だけに限定しない。

利用可能な材料：
- 当初の意図・成功の基準、実際にしたこと、結果、制約、時系列、ログ、成果物、関係者からのフィードバック
- 批評結果（任意）
- 内省結果（任意）：`Observation / Report / Hypothesis / Unknown`、暗黙の前提、別解釈、不確実性
- 過去の教訓・運用ルールと、その後の経験（あれば）

材料が不足していても、提供範囲を明示して始める。足りない情報をでっち上げない。ユーザーが既に与えた情報を重複して尋ねない。

**モード**：
- **quick（既定）**：短い経験から教訓1〜3件と次回の方針を簡潔に出す。批評・内省の深掘りを自動で強制しない。
- **deep**：重要な仕事、反復する問題、相反する教訓に対して、前提や判断基準の再検討まで行う。長文や問いの無限連鎖は避ける。

## 手順

### 1. 経験を再構成する（AAR）

次の4点を、分かる範囲で短く確認する。

1. 何を目指していたか。
2. 実際には何をした・何が起きたか。
3. 何がうまくいき、何が想定と違ったか。
4. 次に活かせそうな点は何か。

後知恵で当初の目的を書き換えない。結果を批判するだけでなく、成功・偶然の発見・維持したい強みを拾う。観測できる出来事と解釈を分ける。

### 2. 批評・内省を必要な分だけ用いる

- 批評結果が**提供されていれば再利用**する。未提供で成果の評価が必要なら、利用可能な既存の批評スキルを使う。使えなければ簡易評価を明示して進む。架空の批評実行結果を作らない。
- 内省結果が**提供されていれば再利用**する。判断の前提が教訓を左右する場合、`introspection` が利用できればそのスキルを使う。なければ、観測・自己報告・仮説・未知を分けて簡易内省する。**内部の隠れた推論を読んだふりをしない。**
- 何が良かった／悪かったかが自明で、深い内省が有益でなければ呼び出さない。
- 分析は教訓のための手段である。評価や心理的な原因探しを無限に続けない。

### 3. 「教訓」を抽出する

個々の出来事から転用可能な気づきを**原則1〜3件**抽出する。以下のいずれかを含める。

- **続ける**：再利用したい行動、判断、工夫、強み
- **変える**：繰り返したくない判断や手順
- **試す**：次に取り入れたい新しい視点や方法
- **手放す**：価値の乏しい習慣や前提

なるべく「どんな状況では → どうする → なぜ役立ちそうか」の形にする。形式化が不自然な創作上の洞察は、一文の指針・問いのまま残してよい。

**重要な分離**：
- **原因仮説**：「機能を増やすほど良いと思っていた *可能性がある*」
- **採用できる教訓**：「必要性を確認するまで、要求外の機能を自動追加しない」

前者を断定せずとも、後者が現実的で可逆なら採用してよい。

### 4. 学習の深さを選ぶ

- **シングルループ**（基本）：目的や評価軸を維持して、手段・手順・注意点を調整する。
- **ダブルループ**（必要時）：繰り返す問題、価値基準の衝突、意図と結果の根本的なズレがあるとき、目的・成功基準・判断規則自体を問い直す。

ダブルループを毎回実行しない。一般化しすぎた「常に」「絶対」は、具体的な適用条件や例外に直す。

### 5. 有益そうな教訓を暫定採用する

「検証できていない」を理由に、全部を保留しない。次の目安で**採用の強さ**を決める。

| 扱い | 目安 |
| --- | --- |
| **採用** | 有益そうで、負担・副作用が小さく、戻せる。原因の説明が未確定でもよい。 |
| **条件付き採用** | 文脈に依存する、利点と欠点が競合する。適用条件・例外を付ける。 |
| **保留** | コスト、重大な副作用、不可逆性、第三者への影響が大きい。判断に最低限の情報が足りない。 |

採用は**現時点での運用上の方針**であり、過去の原因が証明されたという意味ではない。ユーザーの明示指示、既存のルール、上位の安全・権限境界を上書きしない。

**実行上の境界**：このスキルは次回からの方針案を表明し、同じ会話・許可された作業の中では取り入れてよい。ただし、永続メモリ・AGENTS.md・設定ファイル・他のスキル・リポジトリ・組織規程などを**無断で変更しない**。保存・適用先の変更は明示的な依頼や既存の権限がある場合だけ行う。単に「採用」と書いただけで永続化されたと主張しない。

### 6. 検証は「計画」ではなく自然な再観察を基本とする

- **通常**：次に似た状況が来たら使ってみる。違和感、想定外の副作用、逆の事例が出たら見直す。数値目標、A/Bテスト、仮説検証表、追跡タスクは不要。
- **重要な変更**：高コスト・不可逆・安全性が関わるときだけ、慎重な試行、確認、承認、必要なら正式な検証計画を提案する。
- **変更不能**：戻せない判断や他者に重大な影響がある場合、軽率に採用しない。

不確実なまま実践することは認めるが、「事実」「効果が証明された」という表現に格上げしない。

### 7. 将来使える形で閉じる

出力の主役は「長い反省文」ではなく、**短く再利用できる学び**。同じ教訓を類語で増やさず、優先順位を付ける。必要なら次回の作業に一文のリマインダーを渡す。

過去の教訓と矛盾する経験があれば、古い規則を責めず、**適用条件を狭める／修正する／手放す**。どの学びも改訂可能とする。

## 出力形式（既定）

以下を状況に応じて自然な文章や小さな表で提示する。機械的な全欄埋めは不要。

1. **今回の経験**：目標と結果を1〜3文。
2. **気づき**：良かった点・意外だった点・改善点から重要なものだけ。
3. **学び**：転用可能な教訓1〜3件。原因が未確定なら明記。
4. **次回からの方針**：`採用 / 条件付き採用 / 保留` と、具体的な適用場面。
5. **見直すきっかけ**（任意）：矛盾する事例・負担増・期待した効果がない等。**独立した検証計画は既定で出さない。**

### 最小出力例

> **気づき**：完成度を意識するあまり、意外な構図を早めに捨てていた可能性がある。これは原因の仮説であり確定ではない。  
> **学び**：良さが分からない案でも、すぐ却下せず一度発展させる価値がある。  
> **次回から採用**：構図案を最初に評価する前に、少なくとも一度は大胆な方向へ広げる。制作条件によっては省略してよい。

## 停止条件・禁則

- 教訓が少数得られたら止める。毎回ダブルループ学習や検証を義務づけない。
- 原因仮説を、証明された事実、人格の性質、AIの観測不能な内部動機として記録しない。
- 全ての失敗を個人の責任にしない。制約、環境、偶然、他者との相互作用も考慮する。
- 良い結果を無視せず、**続ける価値のあること**も学習対象にする。
- 1事例から無条件の普遍法則を作らない。強い変更は、適用条件と副作用を確認する。
- 提供されていないログや過去の経験を捏造しない。
- 永続的なルール変更や他ファイルの編集を、振り返り実行の副作用として行わない。
